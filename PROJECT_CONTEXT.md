# Project Context

## Product
Build an original BESS Peak-Shaving Learning Studio. It is an educational simulator, not a production energy-management controller.

## Reference
https://ems-simulator.vercel.app/

The intended learning journey is: building load → demand-charge problem → battery sizing → dispatch simulation → thermal limits → uncertainty → safety faults → design history → economics → assessment.

## Required learning modules
1. Load-profile upload/sample scenarios
2. Battery capacity, power, and threshold sizing
3. 24-hour dispatch simulation
4. Thermal derating
5. Monte Carlo uncertainty testing
6. Fault-response training
7. Decision history / scenario versions
8. Economics and viability
9. Dynamic knowledge check

## Non-negotiable quality requirements
- Original branding, language, visuals, and implementation; do not copy proprietary assets or wording.
- One authoritative calculation engine shared by all modules.
- Every route must support direct navigation and reload.
- Show assumptions and distinguish technical feasibility from financial viability.
- Accessibility, responsive behavior, and test evidence are delivery requirements.

## Known reference weaknesses to improve
- Fresh deep links can fail.
- Sizing and results can show inconsistent outcomes.
- The flow is dense; provide Guided Learning and an advanced Scenario Studio approach.

## Status
Governance is established. No technical stack or implementation case has been approved yet.
